# Convert the desktop vertical slice to IWSDK

The bundled Three.js prototype is deliberately a browser-first logic/UI slice. For competition, use the official IWSDK project generated by the current `npm create @iwsdk@latest` flow; do not assume internal APIs from an older SDK release.

## Integration sequence
1. Generate a clean IWSDK app and confirm its sample scene starts.
2. Keep the generator's `iwsdk.config.json`, `src/index.ts`, scene manifest, Vite configuration and package versions intact.
3. Port the static factory geometry from `FactoryVersePrototype.ts` into the generated scene using standard Three.js objects.
4. Extract state transitions (`pending → selected → placed → inspected`) into a small assembly state module independent of input device.
5. Replace desktop raycast selection with the current IWSDK grab/poke interaction systems from the official `Grab` and `Poke` examples. Ensure all actions can be completed with hand tracking; never make mouse or controller the only route.
6. Add clear visual feedback: target outline, snap animation, wrong-sequence feedback, pass/fail result and reset.
7. Use the official IWER / Immersive Web Emulator. Test both desktop fallback and immersive session. WebXR immersive sessions require HTTPS and a user gesture.
8. Validate on a real supported Meta device before final submission if possible; emulator success alone does not establish Quest compatibility or 60 FPS performance.

## Hand interaction acceptance tests
- Pinch/grab each component from a comfortable seated position.
- Release/snap component onto the correct fixture.
- Recover from wrong selection without locking the app.
- Complete all 3 steps and run inspection with hands only.
- Reset, pause/resume, and re-enter without losing the session or leaving orphan objects.
- Keep targets in the comfortable field of view and avoid requiring large arm/body movement.
